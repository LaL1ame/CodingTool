# state14 命令注册与分发机制 Spec

## 背景

CodePilot 目前只有一套 **ad-hoc 命令链**（state13 前逐步累积）：

- `codepilot/commands.py::parse_command()` —— 硬编码 `if/elif`，返回 `(command, rest)`。
- `codepilot/ui/app.py::_submit()` —— 另一个大的 `if/elif` 分发链，每条命令直接调 `self._cmd_*`，**实现强耦合 Textual**（`self.query_one`、`self._mode_state`、`_apply_modes` 等）。
- 现有命令：`exit /plan /do /mode /auto|manual|strict /edits /compact /continue /memory /forget`。

问题：
- **无通用注册机制**——每条命令的元数据（名称/别名/描述/用法/类型）都散落在 if-链里，无法被 `/help`、Tab 补全、启动期冲突检测复用。
- **命令实现绑死渲染框架**——换一套 UI 就得重写所有命令。
- **行为耦合**——命令与对话发送、模式切换、状态刷新纠缠在 `_submit` 一个函数里。

目标：把这套 ad-hoc 链**泛化成「注册中心 + 分发器 + 界面控制接口」的统一机制**，让用户用斜杠开头的输入绕过 Agent，直接执行本地操作或触发预设提示词——常用操作响应快、省 Token、行为确定，不让 LLM 处理清屏、查状态这类非对话杂事。

## 目标

- 提供命令注册中心，集中管理每条命令的元数据（名称、别名、描述、用法、类型、参数提示、处理函数），并支持隐藏命令。
- 启动阶段即校验注册合法性，别名/名称冲突**直接失败退出**，不等运行时再炸。
- 提供统一解析器：斜杠前缀、首空格前为命令名、命令名小写不敏感、空输入早返回、未命中给出 `/help` 引导。
- 命令按执行模式分为三类：纯本地 / 影响界面 / 预设提示词送 AI。
- 抽象一层**界面控制接口**，让命令实现不绑定具体渲染框架；状态栏联动模式标记 `[DEFAULT]/[PLAN]`。
- 在用户提交入口加**分流器**：命令走本地分发，非命令才交给 Agent。
- 支持别名与 Tab 补全：单匹配直接补、多匹配弹菜单、隐藏命令不参与。
- 内置一组高频命令，并迁入现有全部命令，统一承载。

## 功能需求

### F1 命令注册中心
- 每一条命令以注册条目**集中登记**，条目包含：名称、别名、简短描述、用法示例、命令类型、处理函数；另可带可选参数提示、隐藏标记。
- 提供注册接口，接受一条命令的完整定义。
- 启动阶段对全部注册做**合法性校验**：命令名/别名空、重复撞车（两个不同命令共用同一名称或别名）都要被检出。
- 检出冲突时**立即失败退出（panic/exit）**，带清晰报错信息说明哪个名称/别名撞了哪两个命令，绝不延迟到运行时。

### F2 解析器
- 识别斜杠前缀：以 `/` 开头的输入视为命令调用。
- 命令名取首个空白符前的部分；之后为参数（去首尾空白）。
- 命令名转为小写匹配，做到大小写不敏感（`/CLEAR` ≡ `/clear`）。
- 空输入（全是空白）早返回，不进入命令逻辑。
- 解析未命中任何命令时，给出 `/help` 引导提示，并保留原始输入供用户参考。

### F3 命令类型
每条命令归属三类执行模式之一：

- **纯本地（LOCAL）**：纯计算/查询或本地副作用，不改变 UI 状态机、不进对话。例：`/help`、`/status`、`/session`、`/exit`、`/memory`（读）。
- **影响界面（UI）**：改变界面或应用状态机（切模式、清屏、压缩、调度续跑、改状态）。例：`/clear`、`/plan`、`/do`、`/mode`、`/edits`、`/compact`、`/continue`、`/forget`、`/permission`。
- **预设提示词送 AI（PROMPT）**：把一段预设提示词送进对话交给 AI，行为由 AI 产出。例：`/review`。

统一处理函数契约：`handler(ctx, params) -> 消息 | None`——返回一条用户消息则交给分发器**转发给 AI**；返回 `None` 表示已本地处理完毕。这让「`/plan`/`/do` 带消息落回对话」「`/review` 送提示词」走同一回路。

### F4 界面控制接口
- 抽象一层界面控制接口，封装命令需要的全部界面能力：显示消息、发送用户消息（进对话）、切换模式（计划/执行轴）、查询 Token/上下文用量、刷新状态栏、清空屏幕显示。
- 命令实现只依赖这层**接口**，不 import 具体渲染框架（如 Textual）。
- 当前 TUI App 实现该接口；未来换渲染框架只需另实现一套，命令零改动。
- 状态栏联动模式标记：计划模式 → `[PLAN]`，非计划（执行）模式 → `[DEFAULT]`（对应现有 ToolAxis 的 PLAN/BUILD，仅展示标签差异）。

### F5 输入分流器
- 在用户提交（回车）入口放一个分流器：先解析是否为命令。
- 是命令 → 走本地分发（注册表 + 界面控制接口）。
- 非命令 → 原样交给 Agent 进入对话循环。
- 分流不阻塞、不回显给 AI，命令消费的输入不进对话（`/plan`/`/do` 带消息的除外，见类型说明）。

### F6 别名与 Tab 补全
- 命令支持别名，解析时名称与别名等价命中。
- 支持 Tab 补全：输入 `/` 后按 Tab，按当前前缀匹配候选。
- 单命中 → 直接补全填命令名。多命中 → 弹出候选菜单供筛选选择（选择后填入或仍可继续输入）。
- 隐藏命令不参与补全候选。
- 补全以注册表的名称+别名为唯一候选来源，与 F1 元数据一致、无二次硬编码。

### F7 内置命令
迁入现有 all 命令并补齐，构成统一集合（`*` 为本次新增）：

| 命令 | 别名 | 类型 | 描述 | 参数 |
|------|------|------|------|------|
| `/help` * | `/?` | LOCAL | 列出命令集并带用法引导 | - |
| `/exit` | `/quit` | LOCAL | 退出 | - |
| `/plan` | - | UI+转发 | 切计划模式 `[PLAN]`（只读工具），可带消息落回对话 | 消息? |
| `/do` | - | UI+转发 | 退回执行模式 `[DEFAULT]`，可带消息 | 消息? |
| `/mode` | - | UI | 放行策略 manual/auto/strict | 策略 |
| `/auto /manual /strict` | - | UI | 三条单命令别名，分别设放行策略 | - |
| `/edits` | - | UI | 自动编辑开关（无参翻转） | on/off? |
| `/compact` | - | UI | 手动压缩上下文、刷新状态 | - |
| `/continue` | - | UI | 续接暂停的 Agent 循环 | - |
| `/memory` | - | LOCAL | 分组展示当前指令与记忆索引 | - |
| `/forget` | - | UI | 按关键词删除匹配记忆条目（幂等） | 关键词 |
| `/clear` * | `/cls` | UI | 清屏显示、保留历史与上下文（对齐 Claude Code） | - |
| `/session` * | - | LOCAL | 显示当前会话信息 | - |
| `/permission` * | - | UI | 显示当前权限模式与自动编辑状态 | - |
| `/status` * | - | LOCAL | 显示 token/上下文用量/模式/耗时等状态 | - |
| `/review` * | - | PROMPT | 把「审查当前改动」预设提示词送 AI | - |

模式切换由单复数动词表达：`/plan` 进入、`/do` 退回，符合用户要求。

## 非功能需求

- **N1 启动即校验**：注册冲突在启动时检出并失败退出，不延迟到运行时。
- **N2 解析纯函数**：解析逻辑不依赖框架、无副作用、可单测。
- **N3 低耦合**：注册与分发模块不 import 渲染框架，仅依赖界面控制接口。
- **N4 异步兼容**：处理函数可为异步（`/compact`、`/continue` 是 async）；分发器支持协程与同步两类处理器。
- **N5 补全一致性**：补全候选唯一来自注册表名称+别名，隐藏命令不出现。
- **N6 容错**：单命令处理抛错被捕获、显示错误、不影响 App 存活与后续输入；解析失败只提示不崩溃。

## 不做的事（留给后续 Skill 系统）

- **不做用户自顶定义命令**（用户自定义/动态注入命令）。
- **不做动态生成提示词**（预设提示词当前为内置常量；动态拼装留后续）。
- **不做命令级权限控制**（每条命令的授权/白名单留后续）。

## 验收标准

- AC1：注册中心启动校验能检出名称/别名重复与空白，冲突时失败退出并给出明确报错。（对应 F1/N1）
- AC2：大小写不敏感、首空格分隔、空输入早返回、未命中给 `/help` 引导。（对应 F2）
- AC3：三类命令各自按声明执行；`/plan`/`/do` 带消息能正确切换到对应轴并落回对话。（对应 F3）
- AC4：命令实现不依赖具体渲染框架——换一套界面控制接口实现即可复用全部命令。（对应 F4）
- AC5：分流器区分命令与非命令；命令输入不误入对话。（对应 F5）
- AC6：别名响应与原名一致；Tab 单命中补全、多命中弹菜单、隐藏命令不出现。（对应 F6）
- AC7：内置命令全集可解析、可分发；`/status` 状态栏显示 `[DEFAULT]/[PLAN]` 标记。（对应 F7）

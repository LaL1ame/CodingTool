# state16 Hook 系统 Spec

## 背景

CodePilot 的 Agent 生命周期里有很多「触发条件明确、动作固定」的重复工作，目前全靠用户手动盯：写完代码手动跑格式化、想给某类工具调用加安全闸只能改权限规则文件、每次开会话想注入的上下文得靠 `.rules` 或记忆系统绕。权限系统（state6）只管「工具能不能跑」，Skill 系统（state15）管「可复用提示词」，但**没有一个「在生命周期关键时刻自动执行动作」的机制**。

参照 Claude Code 的 Hooks：用户在 YAML 里声明「事件 + 条件 + 动作」规则，系统在会话开始、工具执行前后、每轮开始等时刻自动匹配并执行——格式化、拦截、上下文注入都不再需要人工。

## 目标

- 用「事件 + 条件 + 动作」三要素声明一条 Hook 规则；条件可省略（无条件触发），事件和动作必填。
- 生命周期事件覆盖四层：**会话级、轮次级、消息级、工具级**，外加少量系统级事件。
- **工具执行前事件可拦截**：基于工具参数做细粒度安全策略，拦下后把拒绝原因作为该工具的结果回灌给模型，让模型自行调整（不打断循环）。
- 条件表达式复用权限规则的匹配语法（**本阶段把共享匹配器升级为：精确 / `!`反向 / `/regex/`正则 / glob**），逻辑组合「全部满足」或「任一满足」二选一，不混用。
- 四种动作：**执行 shell 命令、注入提示词（volatile 尾块）、发 HTTP 请求、启动子 Agent（本阶段仅占位）**。
- 执行控制三选项：**只跑一次（会话内）、后台异步、命令超时**；拦截类事件不允许异步。
- Hook 自身失败只记日志，**绝不中断 Agent 主流程**；规则从 YAML 声明式加载，启动时集中校验（fail-fast）。

## 功能需求

### F1 三要素规则模型 + 声明式加载

- 一条 Hook 规则 = **event**（触发时刻，必填）+ **if**（条件，可省略 = 无条件）+ **action**（动作，必填）。
- YAML 声明式配置，两级存放：**项目级 `<workspace>/.hooks.yaml` > 用户级 `~/.hooks.yaml`**；两级规则合并生效（叠加语义，不做同名覆盖——Hook 是叠加，不是 Skill 的覆盖语义）。
- 单个文件缺失/为空忽略；格式错误启动期明确报错（见 F10）。

### F2 事件清单（四层 + 系统级，共 8 个）

| 层 | 事件 | 触发时刻 | 条件可匹配的字段 |
|---|---|---|---|
| 会话级 | `session_start` | 新会话/恢复会话完成 | `resumed`（是否恢复） |
| 会话级 | `session_end` | 退出前 | 无（if 省略） |
| 轮次级 | `round_start` | 每个 agent 轮次开始、调模型前 | `round`（轮次号） |
| 消息级 | `user_message` | 用户消息提交后、送入模型前 | `text`（消息文本） |
| 工具级 | `tool_pre` | 工具执行前、**权限判定之后**——**唯一可拦截事件** | `tool`（工具名）+ 该工具的参数字段（`command`/`file_path`/`pattern` 等） |
| 工具级 | `tool_post` | 工具执行后 | 同 tool_pre，另加 `ok`（成败） |
| 系统级 | `compact` | 上下文压缩完成后 | 无 |
| 系统级 | `stop` | Agent 循环结束（done/paused） | 无 |

> tool_pre 放在**权限判定之后**：权限系统先管「能不能跑」，Hook 再叠加可编程策略，两者职责不混。

### F3 条件表达式

- 共享匹配器升级（`permissions/rules.py` 的 `match_text`），四种语法权限规则与 Hook 条件共用：
  - **精确**：默认，无特殊字符即精确相等
  - **反向**：`!` 前缀（如 `!git *` = 不匹配 git * 的）
  - **正则**：`/.../` 包裹（如 `/^rm -rf/`）
  - **glob**：含 `* ? [` 走 fnmatch
- 逻辑组合：`if.all`（全部满足）或 `if.any`（任一满足），**二选一不混用**；单条件可简写 `if: {tool: run}`（等价 all 一条）。
- 省略 `if` = 无条件触发。

### F4 动作一：shell 命令（`type: command`）

- 字段：`cmd`（命令文本，支持事件字段占位符如 `{file_path}`）、`timeout`（秒，可省走默认）、`async`（后台）、`once`（会话内只跑一次）。
- **拦截语义（设计决策 A）**：在 `tool_pre` 事件上 command 强制同步执行，**退出码非 0 = 拦截**，stderr 文本作为拒绝原因回灌给模型；退出码 0 放行。不引入第五种动作类型——声明式「命中即拒绝」已由权限规则（state6）覆盖，Hook 的拦截定位是**可编程**安全策略（脚本拿到工具名+参数 JSON 做任意判断）。
- **fail-open（设计决策 B）**：tool_pre 命令**异常/超时 → 记日志并放行**（避免 hook 脚本 bug 锁死所有工具）；只有显式非零退出才拦截。

### F5 动作二：注入提示词（`type: prompt`）

- 字段：`text`（支持事件字段占位符）。
- 注入 volatile 尾块（复用 memory/skill 注入缝），每轮重建持续可见；同一规则同一内容去重只钉一份；`/clear` 复位。

### F6 动作三：HTTP 请求（`type: http`）

- 字段：`url`、`method`（默认 POST）、`headers`（可省）、`body`（可省，支持占位符）、`timeout`、`async`、`once`。
- 定位通知型（webhook），响应体不注入模型，只记日志。

### F7 动作四：子 Agent 占位（`type: subagent`）

- 本阶段仅占位：YAML 校验通过、加载正常；触发时记日志「subagent 动作未实现」并跳过，不接真实执行（等 SubAgent 章节对接）。

### F8 执行控制

- `once`：会话内只触发一次（内存标记，**不持久化**，重启会话重来）。
- `async`：后台执行不阻塞主流程；**tool_pre 事件禁止 async**（拦截必须同步出结果），配置即报错。
- `timeout`：command/http 的执行超时；超时按失败处理（记日志 + TUI 提示），tool_pre 超时按决策 B 放行。

### F9 故障隔离与可观测

- Hook 自身任何失败（命令异常、HTTP 错误、动作执行抛错）只记日志 + TUI 系统行提示，**绝不中断 Agent 主流程**。
- 异步动作完成/失败：记 `logs/codepilot.log`（命令、退出码、输出摘要）+ TUI 对话区打一条系统行（如 `[hook] format ok`）。

### F10 集中校验（fail-fast）

启动加载时统一校验，任一违规明确报错：未知事件名、未知动作类型、`all`/`any` 混用、tool_pre 配了 async、正则编译失败、command 缺 `cmd`、http 缺 `url`、条件字段对该事件不存在。

## 非功能需求

- **N1 fail-fast**：规则配置错误（F10 全集）在启动加载时明确报错，不等运行到触发点才暴露；单个文件 YAML 解析失败视同格式错误，不静默吞掉。
- **N2 故障隔离**：Hook 触发后的任何执行失败（命令异常、HTTP 错误、占位符渲染失败）只影响该条 Hook 本身，记日志 + TUI 提示，Agent 主流程、其他 Hook 规则不受影响。
- **N3 低耦合**：Hook 引擎（规则模型/匹配/执行）不依赖 Textual 与 Agent 实现；Agent 通过「事件发射点」感知 Hook，Hook 通过注入缝（volatile 尾块）触达模型——复用 state13/15 的注入通道，不新辟机制；TUI 提示走回调，引擎本身不 import UI。
- **N4 可单测**：匹配器四语法、条件 all/any 组合、规则解析与校验、拦截判定、once/async/timeout 语义均为纯逻辑，可无 UI 单测。
- **N5 向后兼容**：不破坏权限判定链路（tool_pre 挂在权限之后，权限拒绝的工具根本到不了 Hook）、Skill 白名单收窄、plan 只读过滤、会话恢复、层1/层2 压缩等既有行为；不配 `.hooks.yaml` 时系统行为与现状完全一致（零 Hook = 零开销短路）。
- **N6 性能底线**：同步 Hook（tool_pre/tool_post）单条默认超时可配，避免拖慢工具执行；无条件规则匹配是 O(规则数) 的纯字符串操作，不引入网络/IO 到判定热路径（http 动作默认建议 async，文档写明）。

## 不做的事

- **不做子 Agent 动作的真实运行**——`type: subagent` 本阶段仅占位（F7），等 SubAgent 章节对接。
- **不做 `once` 标记的持久化**——只跑一次仅会话内有效，重启会话重新计数。
- **不做 Hook 执行顺序的显式优先级**——同一事件命中多条规则时按声明顺序执行，不提供 priority 字段。
- **不做 Hook 规则的运行时编辑 UI**——改规则 = 改 YAML 文件后重启会话（`/reload` 热重载 Hook 留后续，state15 的 reload 只覆盖 Skill）。
- **不做事件清单外的新事件**——9 个事件为本阶段全集；「工具结果内容匹配」（读 tool_post 的输出文本做条件）这类深度匹配留后续。
- **不做拦截的人工回环**——tool_pre 拦截是机器判定，不接「是否仍然执行？」确认框（那是权限系统 ask 语义的职责，不重复造）。
- **不做 HTTP 响应注入模型**——响应体只记日志，不进上下文（避免异步不可控注入，沿用「异步结果不喂模型」决策）。
- **不动权限系统的判定语义**——共享匹配器升级（反向/正则）对权限规则是**新增可用语法**，既有 `精确+glob` 规则行为一字不变。

## 验收标准

- **AC1**：项目级 `.hooks.yaml` 与用户级 `~/.hooks.yaml` 的规则合并生效；文件缺失/为空时系统行为与现状完全一致；YAML 格式错误启动期明确报错。（F1/N1/N5）
- **AC2**：8 个事件各自在对应生命周期时刻触发——配一条全事件 prompt 注入 Hook，会话从启动到结束可观察到 8 个事件均被命中（会话级在启停、轮次级在每轮、消息级在提交、工具级在调用前后、系统级在压缩/停止）。（F2）
- **AC3**：条件四语法全部生效——精确、`!`反向、`/regex/`正则、glob 各自命中与不命中的行为正确；`all` 全满足才触发、`any` 任一满足即触发；省略 `if` 无条件触发；权限规则同步获得反向/正则语法且既有规则行为不变。（F3/N5）
- **AC4**：tool_pre 拦截链路完整——命令退出码非 0 时该工具不执行，stderr 文本作为该工具的结果（错误形态）回灌模型，模型在后续轮次中据此调整；命令异常/超时记日志并放行；权限拒绝的工具不触发 tool_pre。（F4/N5）
- **AC5**：prompt 注入后内容出现在 volatile 尾块、每轮重建持续可见；同一规则同一内容只钉一份；`/clear` 后复位。（F5）
- **AC6**：http 动作按配置发出请求（方法/headers/body 占位符正确渲染）；响应只记日志不进上下文；失败记日志 + TUI 提示，主流程不受影响。（F6/N2）
- **AC7**：subagent 占位规则正常加载校验，触发时记日志「未实现」并跳过，主流程不受影响。（F7）
- **AC8**：`once` 规则会话内只触发一次（重启后重新计数）；`async` 规则不阻塞主流程，完成/失败有日志 + TUI 系统行；`timeout` 到期按失败处理；tool_pre 配 async 启动即报错。（F8/F9）
- **AC9**：F10 全集校验逐项可复现——未知事件/动作、all/any 混用、正则非法、command 缺 cmd、http 缺 url、条件字段不存在，各自启动期报出明确错误。（F10/N1）
- **AC10**：不配任何 Hook 时，既有 391 测试全绿无回归；权限、Skill、plan 模式、会话恢复、压缩的既有行为不变。（N5）

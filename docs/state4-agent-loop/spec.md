# CodePilot Agent Loop Spec

## 背景

上一章装好了工具系统：CodePilot 已从"聊天"升级为能读文件、改代码、跑命令的 Agent。但当前 Agent 是**单轮**的——收到用户消息后，模型至多调一次工具、拿到结果、生成最终回复就停止。遇到需要多步完成的任务（先读 A 再看 B、改完 C 再跑测试验证），用户必须一轮轮手动催，模型无法自主推进到完成。

本章给 CodePilot 装上 **Agent Loop**（ReAct 循环）：让模型"先想 → 调工具 → 看结果 → 边做边调整"，自动循环直到任务完成或命中停止条件，从"被动应答"变成"真正能自主干活的 Agent"。

## 目标

- 实现 ReAct 循环：反复「调用模型 → 执行工具 → 回写结果」，直到模型不再请求工具
- 建立完整停止条件体系（正常完成、迭代上限、用户取消、连续未知工具、流出错），迭代上限作为兜底安全网
- 以异步事件流解耦 Agent 与界面，事件覆盖文本、工具调用、工具结果、Token 用量、进度
- 流式文本双路处理：实时推给界面 + 完整累积供后续判断与回灌
- 单轮多工具调用按安全性分批：只读并发、有副作用串行
- Plan Mode 两段式：`/plan` 只放开只读工具出计划，`/do` 切回全工具执行

## 功能需求

- **F1: ReAct 循环** — 收到一条用户消息后，Agent 进入循环：调用模型 → 若模型请求工具则执行并回写结果 → 再次调用模型，如此往复，直到模型产出最终文本且不再请求工具。单条用户消息可自动完成任意多轮。

- **F2: 停止条件** — 循环在以下任一条件满足时立即停止：
  1. 模型产出最终文本且不再请求工具（正常完成）
  2. 达到迭代上限（默认 10 轮，可配置）—— 兜底安全网
  3. 用户按 Esc 取消
  4. 连续多次（默认 2 次）请求不存在的工具
  5. 流式响应出错（HTTP 错误、连接中断等）

- **F3: 异步事件流** — Agent 以异步事件流对外输出，事件类型包括：文本增量、工具调用、工具结果、Token 用量、进度（当前轮次 / 迭代上限）。界面只消费事件、被动渲染，不感知循环内部状态。

- **F4: 流式双路收集** — 每轮流式响应中，文本增量一边实时推给界面，一边累积为完整响应，供本轮结束后判断（是否含工具调用、最终回复内容）和回灌对话历史使用。

- **F5: 工具安全性分批** — 每个工具声明"是否只读 / 无副作用"。单轮返回多个工具调用时：只读工具（read / glob / grep）并发执行；有副作用的工具（write / edit / run）逐个串行执行，副作用工具之间绝不并发。

- **F6: Plan Mode 两段式** —
  - `/plan`：切换到计划模式，本轮起只允许只读工具（read / glob / grep）。模型探索后输出计划文本，随后停留在只读态等待用户下一步。
  - `/do`：切回正常模式，放开全部工具执行。
  - 计划模式下模型调用非只读工具会被拒绝，并以错误回传引导其改用只读工具。

- **F7: 取消循环** — 循环进行中用户按 Esc：立即停止发起新请求、中断进行中的工具执行、回到输入状态，并向界面输出一条取消提示。

- **F8: 多轮工具结果回灌** — 每轮工具执行结果按协议格式回灌对话历史，作为下一轮模型调用的输入，复用上一章的回灌逻辑。

## 非功能需求

- **N1: 界面不阻塞** — 循环、流式接收、工具执行期间，TUI 保持可响应、可滚动。

- **N2: 兜底安全网** — 迭代上限默认 10 轮、可配置，防止死循环；达到上限时给出明确提示。

- **N3: 取消即停** — Esc 后不发起新请求，进行中的工具执行被中断，输入框立即恢复可用。

- **N4: 现有功能不退化** — 纯文本单轮对话、单轮工具调用（模型调一次就停）的行为与上一章完全一致。

- **N5: 协议无关** — 循环逻辑不依赖具体协议（Anthropic / OpenAI），仅通过事件流与统一表示交互。

- **N6: 退出整洁** — 取消或退出时，终止所有进行中的异步任务、清理临时状态、恢复终端。

## 不做的事

- 权限系统 / 工具权限分级（现有 `run` 命令确认保留，本章不新增分级）
- 上下文压缩 / 窗口管理
- 用户交互式确认（计划审批弹窗、逐工具批准等——`/plan` 到 `/do` 的切换由用户手动敲命令完成，不设额外确认 UI）
- Agent 自动重试 / 指数退避
- 会话持久化
- MCP 集成
- 多 Agent / 子 Agent 编排
- Token 用量统计的持久化与计费（本章仅实时展示）

## 验收标准

- **AC1 (F1)**: 发送一个需多步工具调用的任务，Agent 自动完成多轮，直到模型不再请求工具，无需用户逐轮催促。
- **AC2 (F2)**: 模型直接回复文本、不请求工具时，循环一轮即停，行为与上一章单轮对话一致。
- **AC3 (F2)**: 构造一个每轮都请求工具的模型响应，循环在迭代上限（默认 10）轮后停止，并给出明确提示。
- **AC4 (F2)**: 模型连续 2 次请求不存在的工具，循环停止并报错。
- **AC5 (F2)**: 流式响应返回 HTTP 错误时，循环停止并显示错误。
- **AC6 (F2/F7)**: 循环进行中按 Esc，循环立即停止、不再发起新请求、进行中的工具被中断。
- **AC7 (F3)**: 一次完整的多轮对话中，事件流依次产出文本、工具调用、工具结果、进度、Token 用量事件；界面仅靠消费事件即可完成渲染。
- **AC8 (F4)**: 流式期间界面实时显示增量文本，同时对话历史最终保存完整回复。
- **AC9 (F5)**: 单轮同时返回多个只读工具调用时并发执行（总耗时 ≈ 最慢者）；同时返回多个副作用工具调用时串行执行（总耗时 ≈ 各自之和）。
- **AC10 (F6)**: `/plan` 下模型调用 write / run 被拒绝并回传错误，调用 read / glob / grep 正常；`/do` 后恢复全工具。
- **AC11 (F6)**: `/plan` 输出计划后停留在只读态，直到用户敲 `/do` 才放开执行。
- **AC12 (F8)**: 第二轮模型调用能看到第一轮的工具执行结果（按各协议原生格式回灌）。
- **AC13 (N1)**: 工具执行与多轮循环期间，TUI 可正常滚动对话区。
- **AC14 (N4)**: 上一章全部单元测试（58 个）继续通过，无回归。
- **AC15 (N2)**: 迭代上限可通过配置修改。
- **AC16 (F3)**: 每轮结束后，界面能展示本轮 Token 用量。
- **AC17**: 端到端 — 真实 API 下发送"读 app.py 并总结"，Agent 自动完成、无需催促。
- **AC18**: 端到端 — 真实 API 下发送一个需改代码并验证的任务，Agent 循环直至完成。
- **AC19**: 端到端 — `/plan` 让模型探索并输出计划 → 用户敲 `/do` → 模型执行计划。

# state13 长期记忆 Spec

## 背景

CodePilot 当前没有跨会话的长期记忆：

- **state12 已完成短期记忆层**——会话中断后能恢复本轮上下文（消息序列、工具轨迹、时间提醒），解决「中断→重启接着用」。
- **但长期知识零持久**——项目约定、你的偏好、踩过的坑，换个会话就全部失忆，每次都要重新解释。

目标是给 CodePilot 装上 **长期记忆**：既吸收「你明说」的规则（手写指令文件），也吸收「它自己学会」的偏好（自动笔记），并把它们揉进每个会话的 system prompt，让 Agent 从「每次失忆」变成「越用越懂你」。

## 目标

- 提供一个**手写**的项目/用户指令入口，让用户能长期、稳定地告诉 Agent 项目约定与个人偏好。
- 提供一个**自动学习**的笔记通道，Agent 在每次自然完成一轮会话后，把值得记住的信息沉淀下来。
- 把指令与记忆**注入**到每个会话的 system prompt，且不显著增加上下文开销。
- 让用户能**查看与删除**系统记住了什么，保持透明可控。

## 功能需求

### F1 指令文件加载（三层 + 优先级）
系统在每次构建 system prompt 时读取手写的指令文件，分三层：

| 层 | 位置 | 语义 |
|----|------|------|
| 用户级 | 用户主目录下的指令目录 | 跨项目通用的个人偏好与习惯 |
| 项目级 | 项目根的指令目录 | 本项目全局约定 |
| 子目录级 | 项目内子目录的指令目录 | 该子目录最局部的约定 |

三层按「用户级 → 项目级 → 子目录级」的优先级依次叠加，越具体（越深的层）越靠后、更贴指令尾部。同层内多文件按约定顺序拼接。加载失败（文件损坏/缺失）不阻塞会话——静默跳过并记录日志。

### F2 @include 引用
任一指令文件可用 `@include <相对路径>` 引用其它 Markdown 文件，作为原地展开。展开需满足：

- **深度限制**：嵌套不超过 N 层。
- **防环**：已访问的文件不再重复展开（visited 集合）。
- **防逃逸**：引用路径不允许越出指令目录范围。

某次 include 解析失败（找不到/超限/逃逸）时，只跳过该处引用、保留主文件其余内容，不整体失败。

### F3 自动笔记存储（四类 + 目录分隔）
系统维护机器生成的记忆笔记，分四类：

- 用户偏好（你喜欢的工作方式、命名、格式）
- 纠正反馈（你纠正过 Agent 的错误或误解）
- 项目知识（本项目结构、约定、踩过的坑）
- 参考资料（有用的外部链接/命令/依赖）

笔记按「用户级」与「项目级」分目录存放；用户级的只写你的个人偏好/反馈，项目级写该项目的知识/资料。所有笔记均不进版本控制——属机器生成数据。

### F4 自动记忆触发（每轮自然停 → 后台异步写）
每次 Agent 循环「自然停」（done、本末无工具调用）后，系统启动一个**后台任务**：

1. 把本轮对话（用户的请求 + Agent 的工具轨迹与最终回答）交给 LLM 压缩一次；
2. LLM 产出 0..N 条笔记并按四类归类、与既有笔记去重（去重逻辑交给 LLM 判断）；
3. 异步写回对应目录的文件；完成后即忘，不等待、不阻塞 UI、不占用后续轮次。

写失败的笔记不阻塞会话，仅记录日志。多个后台写彼此独立，失败互不影响。

### F5 记忆注入到 system prompt
每个会话每一轮构建 system prompt 时，把「指令文件拼接结果 + 当前记忆索引」作为一个**动态尾块**注入。注入内容由两层构成：

- 指令（F1/F2 的展开结果，相对稳定）
- 记忆索引（F3 的笔记摘要，随记忆增长）

注入块有**大小上限**：总长不超过约 200 行 / 25KB；超限时截取或抽要，确保不挤占上下文预算。动态尾块位于缓存断点之后、不进缓存（对齐现有 plan 指令块的机制）。

### F6 看/删命令
系统提供两条交互命令：

- 查看：列出当前注入的记忆内容，按四类分组展示。
- 删除：按关键词删除匹配的记忆条目；无关条目不受影响，删除幂等。

## 非功能需求

- **N1 注入开销可控**：记忆注入块有硬上限（200 行/25KB），且置于缓存断点后，不污染稳定前缀的缓存。
- **N2 异步不阻塞**：自动记忆的 LLM 调用与文件写入均为后台任务，不拖慢用户输入回显、不阻塞后续轮次启动。
- **N3 读只读、删精确**：读取记忆幂等、无副作用；删除仅删精确匹配条目。
- **N4 目录纪律**：机器生成数据（会话、笔记）不进 git；手写指令文件由用户自行版本管理。
- **N5 容错**：任何单个文件读取、解析、include、写入、LLM 调用失败，只跳过该项并记日志，不使会话崩溃。

## 不做的事

- **不使用向量库 / RAG**做语义检索，记忆索引就是文件摘要拼接。
- **不做团队记忆同步**，多用户共享记忆留后续。
- **不做记忆自动过期/清理**，目前只通过 /forget 删除（30 天清理已由 state12 覆盖会话文件，不覆盖笔记）。
- **不自动改写用户手写的指令文件**——机器只写自动笔记，不动手写指令。
- **不做记忆的实时流式 UI**——记忆的查看/删除仅通过命令，不画进 RichLog。
- **`/forget` 只删自动笔记，不删手写 `.mewcode` 指令**（真机验收确认）。二者删除路径刻意分开：

  | 内容 | 存放 | 删除方式 |
  |------|------|---------|
  | 自动笔记（偏好/纠正/项目知识/资料） | `~/.codepilot/.../memory/*.md` | `/forget`（子串删整条 bullet，safe：派生缓存） |
  | 手写指令 | `.mewcode/*.md` | 手动编辑/删除该源文件（不提供 `/forget`） |

  理由：`.mewcode` 是用户**源文件**（structured Markdown，可能含 `@include`/标题/代码块），子串粗删会切碎；自动笔记是**派生缓存**，粗删可再生成，故 `/forget` 只面向后者。

## 验收标准

- AC1：三层指令文件的内容按「用户级→项目级→子目录级」顺序拼进注入块；缺失/坏文件被跳过且不崩溃。（对应 F1）
- AC2：`@include` 正确原地展开；嵌套超限、出现环、路径逃逸时只跳过该引用、主文件其余内容保留。（对应 F2）
- AC3：四类笔记按用户级/项目级分目录落盘；目录不进版本控制。（对应 F3）
- AC4：某会话自然停后，后台自动产生 LLM 压缩并落笔记；UI 不因此卡顿，会话可立即继续。（对应 F4）
- AC5：下一个会话的注入块包含新记忆；无记忆/无指令时注入块为空或占位，上下文开销不超上限。（对应 F5）
- AC6：查看命令展示按四类分组的内存内容；删除命令按关键词精确删条目、再次删除无副作用。（对应 F6）
- AC7：某一指令文件损坏或 LLM 写失败时，会话正常运行不崩溃。（对应 N5）

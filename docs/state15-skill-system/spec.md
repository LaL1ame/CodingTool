# state15 Skill 系统 Spec

## 背景

用户在 CodePilot 里反复输入同样的提示词（review 改动、commit 信息、跑测试等）。目前这类操作散落在各处的硬编码提示词里——例如 state14 的 `/review` 就是一个写死的 PROMPT 命令（把一段预设提示词送 AI）。没有一个统一的、可复用的、带元信息的能力容器，用户无法自顶定义自己的可复用操作。

目标：把「可复用的 AI 操作」封装成独立的 Markdown 文件（Skill），打上元信息，采用两阶段加载（启动只注入名字+一句说明，用的时候再按需加载完整指令）与两种执行模式（共享当前对话 / 开独立对话跑完回流摘要），并用工具白名单收窄模型可选工具、提升选对工具的准确率。

本模块是 state14 「不做的事」里明确的后续：state14 明确「不做用户自定义/动态注入命令」，留给 Skill 系统；本阶段正是它的承接。

## 目标

- 提供统一的 Skill 描述格式：YAML frontmatter（元信息）+ Markdown 正文（SOP 指令）。
- 三级存放，同名按优先级覆盖（项目 > 用户 > 内置）。
- 两阶段加载：启动把名字+一句说明注入对话；按需由内置工具加载完整指令。
- 激活后的完整指令每轮重建都出现在环境上下文最显眼位置，多个 Skill 可同时激活。
- 两种执行模式：共享当前对话、结果留主历史；独立对话、跑完回流摘要并能带指定条数历史。
- 工具白名单收窄当前可用工具；启动时白名单里出现不存在的工具立刻报错；加载工具本身不受白名单约束。
- 加载完自动注册成斜杠短命令、支持热更新；清空对话时顺带清掉已激活 Skill。
- 内置 commit、review、test 三个样板。
- 不做市场分发与版本管理。

## 功能需求

### F1 文件格式：frontmatter + Markdown 正文
- 单个 Skill 用 YAML frontmatter + Markdown 正文描述；frontmatter 放元信息，正文是发给模型的 SOP 指令。
- frontmatter 字段：
  - 唯一名字 `name`
  - 一句话说明 `description`（阶段一注入用）
  - 可见工具白名单 `tools`（激活时收窄可用工具）
  - 执行模式 `mode`：`shared`（共享对话）/ `isolated`（独立对话）
  - 独立模式带多少历史 `bring_history`（仅独立模式有效）
  - 可选 `model`（指定模型，缺省用当前）
- 正文是 SOP 指令，支持参数占位符，加载/执行时用用户传入的内容替换。
- 解析失败（frontmatter 非法 / 缺必填字段）的单个 Skill 文件被跳过并记日志，不阻断整体加载。

### F2 目录型 Skill
- 一个 Skill 既可以是「单文件」，也可以是「目录型能力包」。
- 目录型：目录内放入口 Markdown（`SKILL.md`）、模板、示例、辅助脚本、参考文档，整套作为能力包分发、可整体加载。
- 入口 Markdown 与单文件遵循同一 frontmatter 规范；辅助文件按需随入口一起可用。

### F3 三级存放与优先级
- 三级存放路径：**项目目录 > 用户目录 > 内置**，目录名统一为 `.skills`：
  - 项目级：`<工作区>/.skills/`
  - 用户级：`~/.skills/`
  - 内置级：随包分发的 `codepilot/skills/`
- 同名 Skill（相同唯一名字）按优先级覆盖，只启用高优先级的那份。项目覆盖用户、用户覆盖内置。
- 目录型 Skill 在不同层级可同名，同样按优先级取高者。

### F4 两阶段加载
- **阶段一（启动）**：只把每个可用 Skill 的名字 + 一句话说明注入对话（作为提示的一部分，进 system 动态尾块），不加载正文。让 Agent 知道「有哪些能力、各自干嘛」。
- **阶段二（按需）**：由一个内置工具（`load_skill`）在需要时加载指定 Skill 的完整指令（正文全文 + 依赖的辅助资源 + 白名单）。
- 未加载的 Skill 只有名字+说明在模型视野内，正文在模型视野外。

### F5 激活态最显眼 + 每轮重建 + 可多开
- 被加载/激活的 Skill，其完整指令被钉在环境上下文**最显眼的位置**（动态尾块的固定区段），每个 agent 轮次重建时持续存在，不被遗忘。
- 多个 Skill 可以同时激活，各自完整的指令同屏并列钉住。
- 未激活前，Skill 的正文不进入每轮上下文。

### F6 两种执行模式
- **共享模式（`shared`）**：在当前对话里执行，被激活的 SOP 指令作为上下文的一部分，结果留在主历史里。
- **独立模式（`isolated`）**：开一段独立对话跑完这套 SOP，结束后只把**摘要（结论/产物）回流**到主对话，SOP 执行过程的内部历史不污染主对话；独立对话按 frontmatter 的 `bring_history` 从主对话带入最近 N 条历史作为背景，结果摘要作为一条结论落回主历史。
- 独立模式可选的指定模型：为独立对话覆盖/指定模型。

### F7 工具白名单
- 激活 Skill 时，其 `tools` 白名单**收窄**当前对话暴露给模型的可用工具集——只保留白名单内的工具（外加系统级工具），其余从本轮模型可见列表中隐藏。
- 白名单与只读过滤（plan 模式）取**交集**：plan 下再滤掉白名单中的副作用工具。
- 停用 / 清空 Skill 后恢复全量工具。
- **系统级工具（`load_skill` 及必要的调度工具）不受白名单约束**，任何 Skill 下都保持可见可调——它是逃生门，防止某个 Skill 漏写工具导致用户被锁死。
- 启动扫描时，若某 Skill 的白名单里出现**不存在的工具名**，立刻报错（fail-fast），不静默吞掉。

### F8 加载即注册 + 热更新 + 清空联动
- Skill 被加载/激活后，自动注册成一个斜杠短命令，方便直接触发执行。
- 撞名处理：当 Skill 的命令名与现有命令冲突时，**Skill 版本胜出并统一入口**，既有绑在同一名字的预设能力载荷并入 Skill 正文后退役（例：内置 review skill 采用 `/review`，原 state14 的 `/review` PROMPT 命令载荷并入其正文后移除）。
- 支持热更新：Skill 文件内容变化可重新加载，命令正文与白名单随之更新，无需重启。
- 清空对话（`/clear`）时，顺带清掉当前已激活的 Skill（激活状态与白名单收窄一起复位）。

### F9 内置样板
- 随包内置三个样板 Skill：**commit、review、test**——作为格式与最佳实践范本，也开箱即用。
- 内置样板同样遵循三级优先级，可在项目/用户级被同名覆盖。

## 非功能需求

- **N1 fail-fast**：白名单出现不存在工具、Skill 元数据非法等配置错误在启动/加载时明确报错，不等运行时或模型行为异常才暴露。
- **N2 故障隔离**：单个 Skill 解析失败只跳过该文件并记日志，不影响其余 Skill 与整体启动。
- **N3 优先级确定性**：同名覆盖的层级判定确定、可测（项目 > 用户 > 内置），不含不确定性来源。
- **N4 低耦合**：Skill 的解析、解析结果模型不依赖具体渲染框架或 Agent 实现；分层与现有提示词`memory_blocks`动态尾块机制一致。
- **N5 可单测**：层级解析、frontmatter 解析、占位符替换、白名单收窄、执行模式分流均为纯逻辑，可无 UI 单测。
- **N6 向后兼容**：不破坏 state13 长期记忆注入、state14 命令机制、state12 会话恢复、plan 模式只读过滤等既有行为。

## 不做的事

- **不做市场分发**（Skill 的上传/下载/同步）。
- **不做版本管理**（Skill 的版本号、依赖解析、锁定）。
- **不做命令级细粒度授权**（每条命令的自名单/授权表，state14 遗留项，仍留后续）。
- **不做 Skill 的动态参数收集 UI**（参数占位符用简单替换，不做结构化表单输入）。

## 验收标准

- **AC1**：单个 Skill 文件（frontmatter+正文）与目录型 Skill（入口+资源包）都能被正确解析为同一结构；非法文件被跳过并记日志、不阻断整体。（F1/F2/N2）
- **AC2**：三级存放同名按 项目>用户>内置 覆盖，只启用高优先级那份；不同层级的同名目录型 Skill 同样正确覆盖。（F3/N3）
- **AC3**：启动阶段模型只见名字+一句说明，不见正文；调用加载工具后才见完整指令。（F4）
- **AC4**：激活的 Skill 完整指令每轮重建都出现在环境上下文最显眼区段；多个 Skill 可同时激活并列钉住。（F5）
- **AC5**：共享模式结果留在主历史；独立模式内部历史不污染主对话、只回流摘要，并按 `bring_history` 带入指定条数历史。（F6）
- **AC6**：白名单收窄模型可见工具、与 plan 只读取交集、停用恢复全量；`load_skill` 等系统级工具任何情况下可见；白名单含不存在工具时启动 fail-fast。（F7/N1）
- **AC7**：加载后自动注册斜杠短命令；撞名时 Skill 版本统一入口、旧预设载荷退役；文件内容变化热更新；`/clear` 清空已激活 Skill 与白名单收窄。（F8）
- **AC8**：内置 commit/review/test 三样板可正常解析、可被使用，且可在项目/用户级被同名覆盖。（F9/N3）

> 注：内置三样板与 state14 现有 `/review` 的合并属行为变更，验收时对照 AC7 由实际行为复核。

# CodePilot 工具系统 Spec

## 背景

CodePilot MVP 已跑通纯文本流式对话，支持 Anthropic/OpenAI 双协议。但模型当前只能"说"不能"做"——无法读文件、改代码、跑命令，停留在聊天机器人阶段。

本阶段要装上工具系统，让模型成为能读写代码、搜索文件、执行命令的 Coding Agent。这是从 "Chat" 到 "Agent" 的关键一步。

## 目标

- 定义统一的 **Tool 协议**：名称、描述、JSON Schema 参数、异步执行方法
- 实现 **六个核心工具**：读文件、写文件、搜索文件（glob）、搜索代码内容（grep）、精确替换编辑、执行命令
- 建立 **工具注册中心**，将注册的工具自动转换为 Anthropic/OpenAI 原生 tool 声明格式
- 协议层支持 **流式解析工具调用**（碎片拼接 + 完整 JSON 还原），**Anthropic 与 OpenAI 两种协议**均覆盖全流程，保持跨协议一致体验
- 工具执行带 **超时**与**结构化错误处理**——失败包成结果回传模型（让它调整），不崩溃、不中断会话
- 工具执行结果以标准格式回灌对话历史，模型据此生成最终回复
- 支持单次回复内的 **并行工具调用**（多个 tool_use 并发执行）
- **命令执行始终走用户确认**，**文件操作限制在工作目录内**
- 工具调用在 TUI 以 **Claude Code 风格工具行**呈现（`● Read(path)` + 结果摘要）
- 不做 Agent 循环（模型拿到工具结果后生成最终回复即停止）

---

## 功能需求

- **F1: 统一 Tool 协议** — 每个工具实现统一接口：提供 `name`（工具名）、`description`（用途描述，供模型判断何时调用）、`parameters`（JSON Schema 格式的参数定义）、以及异步 `execute` 方法。工具开发者只需关注接口契约，不需关心注册、协议转换或调用编排。

- **F2: 工具注册中心 & 请求注入** — 提供注册方法，集中登记所有可用工具。支持按名查找。能将已注册的工具列表转换为 Anthropic 和 OpenAI 各自的原生 tool 声明格式（`tools` 数组）。发起每次对话请求时，将工具定义随请求一起发送，使模型知晓可用工具及其参数形态。注册中心与具体协议解耦。

- **F3: 读文件工具 (`read`)** — 接收相对路径（受工作目录约束）、可选的行号范围（offset/limit），以带行号的 cat -n 格式返回文件内容。超出工作目录的路径返回结构化错误。文件不存在或无权限时返回清晰错误信息。

- **F4: 内置 System Prompt** — 在现有 system prompt 基础上补充 Agent 角色说明和工具使用约定：模型应自主判断是否调用工具、如何选择工具、如何根据工具结果调整回答。约定包括：优先用 `read` 确认文件现状再用 `edit`（而非盲目猜测）；错误结果应分析原因并调整参数重试。

- **F5: 写文件工具 (`write`)** — 接收相对路径和文件内容，创建或覆盖文件。自动创建不存在的父目录。路径限制在工作目录内。文件已存在时，仍执行覆盖（不额外确认），但写入前记录覆盖日志。

- **F6: 编辑文件工具 (`edit`)** — 接收相对路径、`old_string` 和 `new_string`。在文件内容中做**原文精确匹配**：匹配到恰好一处 → 替换；匹配到零处 → 返回结构化错误 + 上下文提示；匹配到多处 → 返回结构化错误 + 各处的行号和上下文。

- **F7: 搜索文件工具 (`glob`)** — 接收 glob 模式，在工作目录内匹配文件路径，返回按修改时间排序的文件列表。

- **F8: 搜索代码内容工具 (`grep`)** — 接收正则表达式模式，在工作目录内搜索文件内容，返回匹配的文件路径列表（或带行号的匹配行）。支持大小写敏感/不敏感控制。默认跳过 `.git` 目录。

- **F9: 执行命令工具 (`run`)** — 接收 shell 命令字符串，在工作目录内执行。**每次执行前必须在 TUI 中弹确认框**，显示完整命令，用户批准后才执行。返回 stdout、stderr 和退出码。支持超时控制（默认 120s）。

- **F10: Anthropic 协议流式工具调用解析** — 在已有 Anthropic SSE 流式解析基础上，增加对 `content_block_start`/`content_block_delta`/`content_block_stop` 事件序列的处理。正确区分三类增量：文本增量（text_delta）、思考增量（thinking_delta，接收即丢弃）、工具调用增量（tool_use 类型 content_block，流式拼接 name + JSON 参数碎片，在 content_block_stop 时产出完整结构）。一次回复中可包含一个或多个 tool_use content_block。

- **F11: OpenAI 协议流式工具调用解析** — 在已有 OpenAI SSE 流式解析基础上，增加对 `tool_calls` delta 数组的增量处理。正确区分三类增量：文本增量（delta.content）、思考增量（如有，接收即丢弃）、工具调用增量（delta.tool_calls，按 index 区分不同工具调用，逐段拼接 function.name + function.arguments JSON 片段，最终产出完整结构）。一次回复中可包含一个或多个 tool_call。

- **F12: 跨协议统一工具调用表示** — 无论底层是 Anthropic 还是 OpenAI 协议，流式解析产出的工具调用统一为内部表示：`ToolCall(id, name, arguments: dict)`。上层（Agent、ChatManager、TUI）只与统一表示交互，不感知协议差异。

- **F13: 工具执行与超时** — 所有工具执行走统一的调度入口（Agent）：从统一表示出发，通过注册中心查找工具，调用 `execute`。每次执行带超时（各工具有合理默认值）。

- **F14: 结构化错误结果** — 工具执行失败时（超时、异常、参数无效、权限不足、匹配失败等），返回结构化错误对象（含 `error` 字段 + 可选的上下文提示），作为正常结果注入对话历史。模型据此调整策略，会话不中断。

- **F15: 工具结果回灌对话历史** — 工具执行完成后，将结果按各协议的原生格式（Anthropic: `tool_result` content block；OpenAI: `role: "tool"` message）注入对话上下文，然后发起第二轮模型请求。

- **F16: 并行工具执行** — 当一次模型回复包含多个工具调用时，所有工具并发执行（而非串行）。全部完成后统一回灌结果，再发起第二轮请求。

- **F17: TUI 工具调用展示** — 工具调用和结果在对话区以 Claude Code 风格工具行呈现：开始时显示 `● ToolName(params)`；完成时更新为结果摘要；失败时显示 `✕ Error(message)`。工具行的视觉风格与普通对话消息明显区分。

- **F18: 命令确认列表** — 当模型调用 `run` 工具时，TUI 弹确认列表（Claude Code 风格），显示完整待执行命令和三选项：1. 批准执行 / 2. 拒绝执行 / 3. 始终允许（本次会话）。使用 ↑↓ 键在选项间移动高亮光标，Enter 确认当前高亮项，数字键 1/2/3 直接选择。选项 3 被选后，后续 `run` 调用不再弹确认。确认期间不阻塞其他 UI 响应。

## 非功能需求

- **N1: 界面不阻塞** — 工具执行（含超时等待）与 TUI 渲染互不阻塞。所有工具调用走异步执行，流式接收、工具执行、用户确认弹窗期间，界面保持可响应。

- **N2: 超时保护** — 每个工具设合理默认超时（read/glob/grep: 30s，write/edit: 10s，run: 120s），可配置覆盖。超时后立即中断执行，返回结构化超时错误。

- **N3: 跨协议一致体验** — 无论底层走 Anthropic 还是 OpenAI 协议，用户感知的工具调用行为保持一致。

- **N4: 工具注册解耦** — 添加新工具只需：实现 Tool 接口 → 注册到注册中心。不需要修改协议层、Agent、ChatManager 或 TUI 的任何代码。

- **N5: 结构化错误不崩溃** — 任何工具执行失败均返回结构化错误对象，不抛未捕获异常，不导致会话终止或 TUI 崩溃。

- **N6: 工作目录边界** — 文件操作工具在路径解析后校验：最终路径必须在当前工作目录子树内。`../` 穿越和绝对路径逃脱均被拦截。

- **N7: 密钥不泄漏** — 系统自身绝不在日志、错误或工具结果中打印 API 密钥。

- **N8: 退出整洁** — 含工具调用的会话退出时：终止所有进行中的工具执行，清理临时状态，恢复终端。

- **N9: 现有功能不退化** — 纯文本对话（模型不调用工具时）的行为与 MVP 完全一致。

- **N10: 结果体量控制** — read: 行数上限 2000；glob: 文件数上限 500；grep: 匹配行数上限 250；run: stdout+stderr 总长度上限 8000 字符。截断处附明确标记和原始总量。

---

## 不做的事

- Agent 循环（Agent Loop）：模型拿到工具结果后生成最终回复即停止
- 运行时工具增删：工具集在应用启动时注册完毕，会话中途不动态添加或移除
- 用户自定义工具 / 插件
- MCP 集成
- 工具调用中断：流式期间不支持取消正在进行的工具执行
- 自动重试 / 退避：工具失败不自动重试
- Token 用量统计
- 会话持久化
- 工具结果在 UI 中的折叠/展开
- 多模态工具
- 工具权限分级：仅 `run` 命令需确认，其余工具自动执行

## 验收标准

- **AC1 (F1)**: 新增一个工具只需实现 Tool 接口，无需修改注册中心或协议层代码。
- **AC2 (F2)**: 启动应用后抓取发出的 API 请求，`tools` 字段包含六个工具的完整声明，Anthropic 和 OpenAI 格式各自符合其原生规范。
- **AC3 (F4)**: 发出的请求中 system prompt 包含 Agent 角色说明和工具使用约定。
- **AC4 (F3)**: `read` 工具读取工作目录内文件，返回带行号的 cat -n 格式内容；读取不存在的文件返回错误；越界路径返回错误。
- **AC5 (F5)**: `write` 工具创建/覆盖文件，自动建父目录；路径越界被拒绝。
- **AC6 (F6)**: `edit` 工具唯一匹配替换；零匹配和多处匹配均返回结构化错误。
- **AC7 (F7)**: `glob` 返回匹配文件列表，按修改时间排序；超出上限截断并标记。
- **AC8 (F8)**: `grep` 返回匹配文件路径；支持大小写不敏感；超出上限截断并标记。
- **AC9 (F8 补充)**: `grep` 默认跳过 `.git` 目录。
- **AC10 (F10)**: Anthropic 协议下，模型回复含工具调用时，流式解析正确产出完整 `ToolCall`；文本增量正常流式输出；thinking 增量不出现。
- **AC11 (F11)**: OpenAI 协议下，模型回复含多工具调用时，按 index 正确区分并组装各自的 `ToolCall`。
- **AC12 (F12)**: 同一工具调用场景分别用 Anthropic 和 OpenAI 协议运行，Agent 收到的 ToolCall 内部表示一致。
- **AC13 (F13)**: 工具执行超过默认超时值时，返回结构化超时错误对象，会话不中断。
- **AC14 (F14)**: 各类型失败（文件不存在、权限不足、参数无效、超时）均返回含 `error` 字段的结构化结果。
- **AC15 (F15)**: 工具执行完成后，后续 API 请求中包含正确格式的 tool_result。
- **AC16 (F16)**: 单次回复含多个工具调用时，并发执行（总耗时 ≈ 最慢那个）。
- **AC17 (F17)**: 工具调用期间对话区出现 `● ToolName(params)` 行；完成后更新为结果摘要；失败时显示 `✕ Error(message)`。
- **AC18 (F18)**: 模型调用 `run` 工具时，TUI 弹出确认列表（三选项：批准/拒绝/始终允许）。↑↓ 切换高亮，Enter 确认，数字键 1/2/3 直达。"始终允许"被选后，同会话后续 `run` 调用自动批准。
- **AC19 (N1)**: 工具执行期间，TUI 可正常滚动对话区。
- **AC20 (N6)**: 所有文件类工具对越界路径返回错误。
- **AC21 (N9)**: 发送不涉及工具的普通对话消息，行为与 MVP 完全一致。
- **AC22 (N10)**: read/grep/run 超限时截断并标注原始总量。
- **AC23**: 端到端 — Anthropic 协议下，"帮我读 app.py"触发工具调用全流程。
- **AC24**: 端到端 — OpenAI 协议下，"创建 hello.py"触发工具调用全流程。
- **AC25**: 端到端 — 命令确认弹窗拒绝后模型正常应对。

# CodePilot 权限系统 Spec

## 背景

当前权限能力是散落的「种子」：
- `validate_path`（工具基类）做**单工具内**的路径沙箱，已 `.resolve()` 解符号链。
- run 工具内置 `confirm_callback`（App 弹 Claude Code 风格确认屏，本次/会话/拒绝），**只有 run** 触发，返回 bool，能力单一。

缺少一套统一的权限判定，无法覆盖「危险命令黑名单、细粒度规则、信任档位、任意工具的人机确认」，且拒绝时行为不统一。

目标：给 Codepilot 装一套**五层防御**的权限系统，作为 agent 唯一执行口上的横切判定。权限被拒绝时**不终止 Agent Loop**，给模型调整策略的机会。

## 目标

- 危险命令黑名单**硬拦截**，不可被配置或档位放开。
- 文件读写限制在项目目录内，**解析符号链接**再判前缀，防路径逃逸。
- 可配置规则按「工具名(模式)」声明 allow/ask/deny，支持精确与 glob。
- 多档权限模式（严格/默认/放行）整体切换信任等级，**只作无规则命中时的兜底**。
- 人在回路：规则未明确命中时交回用户，支持本次（内存）/ 本会话（内存）/ 永久（写规则文件）。
- 规则合并后按 `deny > ask > allow` 判定，与写入层级无关。
- 权限拒绝返回错误结果、**循环继续**，模型可调整。

## 功能需求

- F1：**危险操作黑名单** —— 预置一组正则，在执行任何命令前硬拦截已知高危命令；这一层**不可被规则、档位、人机回路放开**。
- F2：**路径沙箱** —— 限制 read/write/edit/glob/grep 的目标落在项目目录内；**先解析符号链接再做前缀判断**，防 `..` 或软链接逃逸到目录外。
- F3：**可配置规则** —— 规则按「工具名(模式)」声明，结果为 allow/ask/deny；模式的匹配对象按工具取（run → 命令串，文件类 → 路径）；支持精确匹配与 glob 通配。
- F4：**多档权限模式** —— strict / default / permissive 三档；档位**只决定无规则命中时的兜底判定**（strict→deny，default→ask，permissive→allow）；显式 deny 恒拦截。
- F5：**人在回路** —— 当判定为 ask 时，把工具调用交回用户确认；用户可给三种放行：**本次**（仅这一轮）、**本会话**（内存里记到会话结束）、**永久**（写入规则文件）；拒绝则返回 deny。
- F6：**规则优先级** —— 所有来源（用户级/项目级/本地级）规则合并为一套；判定 `deny > ask > allow`，**写在哪一层不影响结果**。
- F7：**拒绝不终止循环** —— 工具被 deny 时返回错误结果并继续 Agent Loop，下一轮模型可读错误、调整策略、重试。
- F8：**三级规则存储** —— 规则按 用户级 / 项目级 / 本地级 三个 YAML 分存，读取时全部合并；层级只决定**永久放行/ deny 写进哪个文件**（本地级优先）。

## 非功能需求

- N1：黑名单为**硬层**，任何配置/模式/人机判定不可绕过。
- N2：人机回路在 TUI 中**不阻塞事件消息泵**（异步唤起确认屏），复用现有异步任务方式。
- N3：兼容现有工具；run 工具从内置确认**迁移**到权限系统统一管理（默认档行为不变，仍会问）。
- N4：规则匹配开销为 O(规则数)，每轮判定不引入明显延迟。
- N5：本次/会话放行**仅驻内存，不落盘**；永久放行写本地级规则文件（可版本忽略）。
- N6：不引入第三方策略引擎，全部自研轻量判定。

## 不做的事（边界）

- 网络请求限制。
- 资源配额（token/时长/内存）。
- 审计日志。
- 规则可视化编辑 / 加密规则源。

## 验收标准

- AC1：高危命令（如 `rm -rf /`）被黑名单硬拦；尝试用规则 allow 或放行档位均**无法**放开。
- AC2：路径逃逸（`../` 越界、符号链接指向目录外）被沙箱 deny。
- AC3：规则精确与 glob 匹配正确（如 `run(git *)` 放行长 git 命令、deny `run(rm *)` 拦删）。
- AC4：三档下无命中结点判定正确（strict→deny、default→ask、permissive→allow）。
- AC5：显式 deny 规则在任意档位下都拦截、不被 permissive 覆盖。
- AC6：ask 时人机回路弹出；本次/会话/永久三种放行分别生效（永久写入本地规则文件、会话内不再问）。
- AC7：工具被拒绝返回错误、Agent Loop 继续（下一轮可收到错误并调整）。
- AC8：同一组规则放不同层级文件，判定结果一致（证明与层级无关）。
- AC9：全量单测通过，新增权限层（黑名单/沙箱/规则/模式/优先级）单测覆盖。
- AC10：端到端 —— TUI 触发一次 ask → 选「永久放行」→ 后续相同调用自动放行、不再弹。

# state17 SubAgent 系统 Spec

## 背景

CodePilot 主 Agent 的上下文是有限且共享的——任何子任务的输出、工具结果、中间推理都会污染主对话的 token 预算与注意力。目前「让模型干一个独立的活」只有两条路：手动开新会话（丢上下文），或 Skill isolated 模式（`_run_isolated_skill`，state15）——但它绑死 Skill 定义、同步阻塞、无后台/任务管理/角色体系。state16 的 `subagent` Hook 动作也明确留了「等 SubAgent 章节对接」的占位。

需要一个正式的 SubAgent 系统：主 Agent 用一个**稳定的 `agent` 工具**把子任务委派给**独立的子 Agent**——它有自己的干净上下文、受限工具集、独立权限追踪，跑完把结论异步送回主对话，彻底隔离上下文污染。

## 目标

- **统一入口**：一个 `agent` 工具，用类型参数分流「定义式」和「Fork 式」两条路径，工具列表始终稳定。
- **角色定义体系**：Markdown + YAML frontmatter 定义（工具白/黑名单、模型、最大轮次、权限模式），四级来源加载、同名覆盖，正文即子 Agent 系统提示。
- **定义式**：从空白对话 + 固定角色启动，跑到底，结果回灌。
- **Fork 式**：继承父对话历史与工具集，借 prompt cache 降首次请求成本，强制走后台。
- **状态隔离、基础设施共享**：消息、权限、读缓存、token 计数各自独立；LLM 客户端、Hook 引擎、文件系统共享。
- **后台任务管理器**：追踪状态/结果/用量，支持三种进后台方式（显式指定、超时自动、手动切）。
- **多层工具过滤防嵌套**：全局禁止 + 角色额外限制 + 后台白名单。
- **结果呈现**：子 Agent 跑完摘要回灌主对话（模型可见）+ TUI 系统行；执行中只显示状态行，完成后一次性摘要。

## 功能需求

### F1 角色定义模型 + 四级加载

- 一个角色 = **YAML frontmatter**（角色名、用途说明、工具白名单、工具黑名单、模型「继承或指定」、最大轮次、权限模式）+ **Markdown 正文**（子 Agent 的系统提示，定义其身份/职责/工作风格，贯穿整个生命周期）。
- 四级来源，**加载优先级从高到低**：项目级 > 用户级 > 内置 > 插件；同名后者覆盖前者。
- 单文件缺失/为空忽略；单个文件解析失败**只跳过该文件并记日志**，不阻断整体加载（延续 Skill 的故障隔离惯例）。
- 字段校验：非法值（未知工具名进白名单、非法模型名、非法权限模式）启动期集中校验，明确报错。

### F2 统一 `agent` 工具（常驻入口）

- 一个名字恒定的 `agent` 工具，**始终在工具列表中**（系统级、不受 Skill/角色白名单约束），工具列表不随角色增删而变动。
- 参数分流两条路径：**定义式**（角色名 + 任务描述）与 **Fork 式**（任务描述 + 继承语义标记）；公共参数：是否后台、超时。
- 工具自身永不失败——失败只发生在子 Agent 内部，以结果形式返回。

### F3 定义式执行

- 从**空白对话 + 固定角色**启动：角色正文作为系统提示，角色的白名单/黑名单/模型/最大轮次/权限模式全部生效。
- **跑到底非交互**：模型不再调用工具即视为完成；无需用户干预。
- 默认**前台同步**：调用方等待子 Agent 完成，摘要作为该工具调用结果回灌。

### F4 Fork 式执行

- 继承**父对话历史与工具集**（作为子 Agent 的初始上下文），首次请求命中 prompt cache 以降成本。
- **强制后台**：不阻塞主 Agent 循环。

### F5 运行时状态隔离 + 基础设施共享

- **各自独立**：消息列表、权限实例（独立追踪、独立模式）、文件读缓存与工具结果 offload、token 用量计数。
- **共享**：LLM 客户端、Hook 引擎、文件系统、工具注册表。
- 隔离是硬性的——子 Agent 的读写、计数、权限判定互不可见、互不影响。

### F6 结果回灌

- **前台**：子 Agent 完成后，摘要作为 `agent` 工具结果回灌模型（主 Agent 可见、可据此继续推理）。
- **后台**：完成后写 TUI 系统行 + 摘要进入主对话上下文（模型后续可见）。
- 摘要为**结构化文本**：结论 + 关键产出（含关键路径/数据），可裁剪到合理长度。

### F7 多层工具过滤防嵌套

- **全局禁止**：子 Agent 默认不可再调用 `agent` 工具（防无限嵌套，深度 = 1）；角色可显式放行但设**深度上限**。
- **角色额外限制**：角色黑名单可显式禁用 `agent`（双重保险）。
- **后台白名单**：后台模式下工具集进一步收窄（更保守的只读子集）。
- 过滤发生在子 Agent 构建工具列表时，多层防线叠加取交集，不是运行时临时判断。

### F8 后台任务管理器

- 追踪每个后台子 Agent 任务的**状态**（运行中/完成/失败/已取消）、**结果**、**token 用量**。
- **三种进后台的方式**：显式指定（参数）、超时自动（前台超限自动转后台）、手动切（用户操作把运行中的前台任务切到后台）；Fork 强制后台。
- 提供**查询任务状态**的入口（命令/视图），用户可查看任务列表与单任务详情。

### F9 故障隔离与可观测

- 子 Agent 任何失败（超时、异常、权限终止、模型错误）**只记日志 + TUI 系统行提示，绝不中断主 Agent 主流程**。
- 每次委派、完成、失败、用量均写日志，可自证（延续本项目的日志可观测惯例）。
- 子 Agent 历史**仅内存**，不落盘、不参与会话恢复（已在范围边界）。

### F10 执行控制

- **超时**：可配；前台超时按 F8 转后台或终止（取决于配置）。
- 取消：后台任务可被取消；前台任务可由用户取消（对齐现有取消语义）。
- 深度与并发上限：同一时刻可运行的后台任务数有上限，超出拒绝新委派并回灌明确原因。

### F11 子任务可视化（增量）

- 有子任务时，输入框上方常驻一行提示（运行中/已完成数量），提示用户可查看。
- **F3** 打开任务列表：**↑/↓** 选择、**Enter** 查看该任务的完整执行轨迹（用户/助手/工具调用/工具结果）、**Esc** 返回列表或关闭。
- 轨迹在子 Agent 结束时一次性保存为扁平快照；运行中可查看已产生的部分（完成后自动刷新）。
- 后台任务完成时，**摘要直接显示在聊天区**（不再需要用户发下一轮让模型转述）；仍按 F6 进入主对话上下文。

## 非功能需求

- **N1 向后兼容**：不配置任何角色、不调用 `agent` 工具时，系统行为与现状完全一致（零角色 = 零开销短路）；既有 482 测试全绿无回归；权限、Skill、plan 模式、会话恢复、压缩、Hook 的既有行为不变。
- **N2 故障隔离**：子 Agent 的任何失败（超时/异常/权限终止/模型错误）只影响该子 Agent 本身，不影响主 Agent 主流程、不影响其它正在运行的后台任务。
- **N3 低耦合**：SubAgent 引擎（角色解析/调度/执行）不依赖 Textual 与 Agent 实现；主 Agent 通过注入的「不透明回调」感知子 Agent 完成（延续 memory/skill/hook 注入缝惯例）；TUI 展示走回调，引擎本身不 import UI。
- **N4 可单测**：角色解析与校验、四级覆盖、工具过滤多层防线、前台/后台调度、超时转后台、深度限制、摘要回灌格式均为纯逻辑，可无 UI 单测。
- **N5 性能底线**：前台同步路径是「子 Agent 内部一轮循环」，无额外网络/IO 进判定热路径；Fork 式首次请求命中 cache 需真机验证（provider 支持时）；后台任务并发受 F10 上限约束，防资源耗尽。
- **N6 一致性**：子 Agent 的「跑到底」停止判定、权限判定、工具执行语义与主 Agent 复用同一套机制（共享引擎），不新造一套行为分歧。

## 不做的事

- 不做 Worktree 文件隔离。
- 不做多 Agent 团队编排。
- 不做后台任务的跨会话持久化（子 Agent 历史仅内存，重启丢失）。
- 不实时流子 Agent 中间输出（仅状态行 + 完成摘要 + 完成后可查看的轨迹快照）。
- 不做从任务面板取消子任务（`manager.cancel` 只改状态的既有缺陷不在本次修复范围）。

## 验收标准

- **AC1**：四级角色加载生效——内置/用户/项目/插件同名角色按优先级覆盖；单文件缺失/解析失败只跳过该文件不阻断；非法字段启动期集中报错。（F1/N1）
- **AC2**：`agent` 工具常驻工具列表且稳定，任何角色/白名单/plan 模式下都不消失；定义式与 Fork 式由参数分流，工具列表本身不变。（F2/N1）
- **AC3**：定义式从空白对话 + 固定角色启动，角色正文生效（身份/职责体现在子 Agent 输出），白名单/黑名单/模型/轮次/权限模式逐项生效；跑到底后摘要回灌。（F3/N4/N6）
- **AC4**：Fork 式继承父历史与工具集，首次请求命中 cache（provider 支持时可观测），强制后台不阻塞主循环。（F4/N5）
- **AC5**：子 Agent 的 token 计数、读缓存/offload、权限判定与主 Agent 独立可观测（各自记日志、各自计数），共享基础设施行为一致。（F5）
- **AC6**：前台调用摘要作为工具结果回灌模型，主 Agent 后续轮次可引用子任务结论；后台完成写系统行 + 摘要进上下文。（F6）
- **AC7**：子 Agent 默认看不到 `agent` 工具（无法再委派）；角色显式放行时可多级但受深度上限约束；黑名单与后台白名单叠加正确。（F7）
- **AC8**：三种进后台方式逐项可复现（显式/超时自动/手动切），Fork 强制后台；任务管理器追踪状态/结果/用量，查询入口可用。（F8）
- **AC9**：子 Agent 失败时主 Agent 继续跑、日志与系统行有明确记录；超时、取消、并发超限各自回灌明确原因。（F9/F10/N2）
- **AC10**：零角色、零委派时既有 482 测试全绿无回归，既有行为不变。（N1）
- **AC11**：有子任务时提示行可见；F3 列表 ↑↓/Enter/Esc 交互正确且选中项不被刷新打断；轨迹含用户/助手/工具调用/结果，协议字符原样显示；后台完成摘要直接出现在聊天区，同时仍进入主对话上下文。（F11）

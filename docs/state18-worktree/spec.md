# Worktree 工作目录隔离 Spec

## 背景

state17 让主 Agent 可以把子任务委派给独立子 Agent。子 Agent 虽有自己的上下文与权限，
但文件操作仍绑定主工作区：主 Agent 与子 Agent、或两个并行子 Agent 同时改文件时，
会互相覆盖，无法真正并行干活。

Git 的 linked worktree 机制允许同一版本库挂载多个工作目录、各自检出一个分支，
共享对象库但工作树互相独立。把每个需要写文件的子 Agent 放进自己的 worktree，
即可获得文件系统级隔离，而不需要复制仓库或引入容器。

本阶段只解决「多个 Agent 在同一仓库里同时改文件」的问题。合并、跨目录同步与多 Agent
编排留给后续阶段。

## 目标

- 角色可通过 frontmatter 声明需要 worktree 隔离；主 Agent 委派时自动创建或复用一个独立工作目录。
- 子 Agent 的全部文件操作、命令执行、权限沙箱与路径相关上下文都限定在 worktree 内。
- 不通过 `chdir` 改变进程工作目录；所有组件显式持有绝对路径，天然支持并行。
- Worktree 有完整生命周期：创建 / 快速恢复 / 进入 / 退出 / 删除 / 过期清理。
- 创建后可自动完成本地配置复制、依赖目录软链、被忽略但运行必需文件的补齐。
- 有未提交改动或未合并提交时默认不删除，避免丢工作；后台清理有三层安全过滤。

## 功能需求

- **F1 角色声明隔离**：角色 frontmatter 支持 `isolation: worktree`；缺省无隔离。
  非法取值在角色加载期立即报错。隔离仅对定义式角色生效；Fork 式本阶段不隔离。
- **F2 命名与安全校验**：`agent` 工具新增可选 `worktree` 参数，仅隔离角色可传；
  省略时自动生成 `<role>-<task_id>`。目录名接受斜杠嵌套，但必须通过严格校验：
  字符集、长度、段数、`.`/`..` 段、空段、反斜杠、绝对路径、Windows 保留名、
  段尾点/空格全部拒绝；解析后的真实路径必须仍在 worktree 根内。
- **F3 创建与快速恢复**：worktree 根固定在主仓 `.codepilot/worktrees/`（该目录被忽略），
  每项从主工作区当前 `HEAD` 建分支 `codepilot/<name>`。目录已存在时只做文件系统检查
  （目录、`.git` 文件、元数据），通过则直接复用、不调用 Git；目录不存在但同名分支存在时
  挂到已有分支；两者都在但被其他 worktree 占用时失败。同一名字在进程内被运行中任务占用时，
  第二个委派被拒绝并提示换名。
- **F4 进入与上下文绑定**：隔离子 Agent 获得独立的工作区上下文：
  文件/命令工具绑定 worktree；环境工作目录、项目指令、记忆索引与笔记、上下文溢出目录、
  权限沙箱全部以 worktree 为根；系统级工具（agent、load_skill 等）共享。
  系统提示中注入一段路径说明，明确其工作目录、分支与「改动留在此目录」。
  Skill 与 Hook 本阶段仍共享主会话。
- **F5 环境初始化**：创建后按内置默认与项目 `.worktree.yaml` 规则初始化：
  复制本地配置（`config.yaml`、`.hooks.yaml`、`codepilot-permissions.local.yaml` 等），
  软链大型依赖目录（`.venv`、`venv`、`node_modules`），按规则补齐被忽略但运行需要的文件。
  规则路径必须落在主仓内；目标已存在不覆盖；源不存在跳过；规则非法或 IO 失败则创建失败并清理半成品。
  Git hooks 默认依赖 Git 共享机制；仅在 `core.hooksPath` 为相对路径或项目存在 `.githooks/` 时
  为该 worktree 做指向修正。
- **F6 退出与保留决策**：任务成功、失败或取消时统一判定：无未提交改动且相对基线无新提交
  → 删除目录、分支与元数据；有任一项 → 保留并在任务摘要中报告路径、分支与原因。
  无论结果如何都释放进程内占用锁。
- **F7 删除与变更保护**：用户删除命令默认拒绝有未提交改动或新提交的 worktree；
  显式 `--force` 可删除目录与未提交改动，但**分支始终保留**，并提示后续合并/删除方式。
  自动删除只发生在 F6 的无变更路径。
- **F8 过期清理**：启动时扫描一次，之后每小时后台扫描；超过 24 小时且未结束的 worktree
  才进入候选。删除前必须通过三层过滤：① 路径在 worktree 根内且解析后不逃逸；
  ② 是带 `codepilot/` 分支前缀的已登记 worktree 且有本系统元数据；③ 未被占用、
  无未提交改动、相对基线无新提交。不满足者只记日志跳过。
- **F9 管理命令**：提供 `/worktree list`（目录、分支、占用、变更状态）与
  `/worktree rm <name> [--force]`；输出走聊天区，不新增独立 TUI 面板。
- **F10 递归扫描隔离**：主 Agent 的项目指令、角色、Skill 递归发现必须剪枝 `.codepilot`；
  `glob`/`grep` 必须跳过 worktree 根，避免主 Agent 把子目录里的文件当成本项目内容。
- **F11 失败与安全边界**：非 Git 仓库、无有效 `HEAD`、Git 命令失败、名称非法、
  同名占用、规则逃逸等一律 fail-closed，直接让委派返回明确错误；绝不回退主工作区。
  非隔离角色或 Fork 误传 `worktree` 参数同样报错。

## 非功能需求

- **N1 显式路径、无 `chdir`**：不得改变进程工作目录；所有 Git 子进程与工具执行显式传入绝对 `cwd`。
  任何路径相关的缓存或派生数据必须以解析后的绝对路径为 key；当前无文件内容缓存，不得新增全局路径缓存。
- **N2 安全**：名称校验、路径包含校验、清理三层过滤均在真实路径（resolve 后）上执行；
  Git 命令使用参数列表而非 shell 拼接；不跟随规则路径逃逸主仓。
- **N3 故障隔离**：worktree 创建/初始化/删除失败只影响对应子任务，不中断主循环；
  清理失败只记录日志，不影响应用运行。
- **N4 可测试性**：名称校验、保留/删除判定、清理候选过滤实现为纯函数；Git 调用可通过注入的
  执行器在临时仓库中单测，不依赖真实用户仓库。
- **N5 跨平台**：Windows 下目录软链失败时回退为 junction；路径处理使用 pathlib 语义，
  不假设 POSIX。
- **N6 向后兼容**：未声明隔离的角色、Fork 式委派与现有工具接口行为不变；
  未配置 `.worktree.yaml` 时使用内置默认即可工作。
- **N7 可观测性**：创建、复用、初始化、保留、删除、清理跳过均写结构化日志，
  包含名称、路径、分支与原因；任务摘要对用户可见。

## 不做的事

- 不做 worktree 之间或回主分支的合并策略（merge/rebase/cherry-pick 交给上层决定）。
- 不做跨 worktree 的代码同步。
- 不做多 Agent 并行编排、调度与冲突解决。
- 不做 Fork 式委派的 worktree 隔离。
- 不做 Skill 与 Hook 的按 worktree 隔离。
- 不做跨进程占用锁（本阶段仅进程内）。
- 不自动安装依赖，只做复制/软链；不复制规则未列出的被忽略文件。

## 验收标准

- **AC1（F1）**：声明 `isolation: worktree` 的角色委派后获得独立目录；未声明角色行为与
  state17 完全一致；非法 `isolation` 值在启动加载期报错。
- **AC2（F2）**：合法嵌套名可创建；`../`、`/abs`、`a//b`、`.`、`..`、超长、非法字符、
  Windows 保留名均被拒绝；显式名称与自动名称都落在一个新分支上。
- **AC3（F3）**：首次创建得到 `.codepilot/worktrees/<name>` 与 `codepilot/<name>`，基于创建时
  `HEAD`；目录已存在且三检通过时不调用 Git 直接复用；同名分支存在时挂接；名字占用时第二个任务失败。
- **AC4（F4）**：隔离子 Agent 的读写与命令只落在 worktree，主工作区文件不被修改；
  其系统提示显示 worktree 路径与分支；项目指令与记忆从 worktree 读取；进程 cwd 始终不变。
- **AC5（F5）**：本地配置被复制、依赖目录成为链接、`include` 规则补齐的文件存在；
  已存在文件不被覆盖；源缺失不失败；非法规则导致创建失败且无残留半成品。
- **AC6（F6）**：无变更任务结束后目录、分支、元数据被清理；有未提交改动或有新提交的任务
  结束后三者保留，摘要含路径与分支。
- **AC7（F7）**：`/worktree rm` 对有变更目录默认拒绝并说明原因；`--force` 删目录但保留分支。
- **AC8（F8）**：超过 24 小时、干净且无新提交的目录被后台清理；有变更、陌生目录、
  非前缀分支、运行中目录均被跳过并记录原因。
- **AC9（F9）**：`/worktree list` 能列出目录、分支、占用与变更状态；`/worktree rm` 行为符合 F7。
- **AC10（F10）**：在 worktree 内放置 `.rules`、角色、Skill 时，主 Agent 的注入与发现不受影响；
  主 Agent 的 `glob`/`grep` 结果不包含 worktree 内容。
- **AC11（F11）**：非 Git 仓库、无 HEAD、名称非法、同名占用等场景下委派返回可读错误，
  主 Agent 继续工作且主工作区无文件变化。
- **AC12（回归）**：全量测试通过且数量不少于基线 584；`ruff check .` 不新增告警；
  未隔离路径的现有测试不修改断言即可通过。

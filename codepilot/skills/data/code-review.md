# 代码自查（当前对话）

在**当前对话**内审查工作区最近未提交改动的质量，结论直接呈现在主对话里（不另开独立对话）。

## 何时使用
- 用户说「帮我检查一下改动/自查一下代码/ review 一下这些改动」但**希望就地审**、结果留在当前对话。

## SOP

1. **摸清改动**：用 run 读 `git status --short` 与 `git diff`（`git diff --staged` 看已暂存）；用 read/grep 通读被改文件及关键调用方，掌握意图。
2. **按四维度逐项检查**，每项标注文件:行号与【等级】：
   - 正确性：逻辑、边界、竞态、API 误用
   - 安全：越权、注入、路径逃逸、secrets
   - 可维护性：结构、命名、重复、职责边界（对照项目 `.rules/` 或 CLAUDE.md 的规范）
   - 边界覆盖：改动是否有对应测试、缺在哪
3. **若改动不明显**：明确说明你观察到了什么。
4. **结论**：列【必须修复】【建议】；这是自查只读，**不擅自改写代码**，如需改由用户点头。
